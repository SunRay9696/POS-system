# The Square Box POS

为马来西亚餐厅 The Square Box 开发的本地演示版：顾客点餐、柜台收银记账、配方扣库存、补货提醒、日／周／月报表，以及财务、库存和营业分析三个经营助理。币种为 RM（MYR），时区为 `Asia/Kuala_Lumpur`，不收服务费。

**目前所有订单，包括现金记账，都是示例交易。电子支付为模拟，没有真实扣款或清算。此版本尚未具备正式营业或公开生产部署条件。** e-Invoice 功能只保存内部草稿，未接入 LHDN / MyInvois。

## 运行与试用

需要 Node.js 24 或更新版本。在仓库目录运行：

```bash
npm ci
npm run dev
```

云环境安装可使用可写缓存：

```bash
npm ci --cache /workspace/.cache/npm
```

默认仅监听本机 `127.0.0.1:3000`。员工入口为 `/`，未配置时的演示 PIN 是 `2468`；顾客点餐入口为 `/order`。首次启动会生成近 30 天的示例订单、费用、库存和配方，并保存至忽略提交的 `data/squarebox.sqlite`。重启保留账目与库存；员工需重新登录。

1. 在员工入口进入点餐收银，选择餐品并记录现金或完成模拟电子支付。
2. 顾客选择柜台付款时只建立待付款订单；员工确认收款后才扣减库存、计入收入。
3. 在点餐页的「菜单与配方」新增或编辑餐品。在库存页新增食材、登记入库、查看当天入库与用量及流水，并设置补货线和目标库存。初始食材与配方是示例，不能代表门店实际成本。
4. 补录人工、租金、水电等费用，再查看本日／本周至今／本月至今的经营报表和 CSV 导出。周报以马来西亚时间的周一开始。
5. 三个助理默认提供规则分析；配置模型后可请求 AI 解读。已付款订单可保存并下载 e-Invoice 内部 JSON 草稿。

开发模式保留前端热更新；修改 `server/` 后需要手动重启服务。

验证及构建：

```bash
npm test
npm run test:e2e
npm run build
npm start
```

浏览器测试使用系统 Chromium（云环境已提供），没有时先运行 `npx playwright install chromium`。测试使用独立临时数据库，不修改试用数据。

`npm start` 使用构建后的页面；这个脚本名称不代表系统已达到生产上线要求。当前服务运行仍使用 `tsx`，安装时需保留开发依赖。

## 配置与边界

可按 `.env.example` 创建本地 `.env`；启动脚本通过 Node 原生 `--env-file-if-exists` 读取。不要覆盖已有配置，也不要提交凭证。若配置了 `STAFF_PIN`，请使用该值登录，不再使用演示默认值。

| 变量 | 用途 |
| --- | --- |
| `STAFF_PIN` | 员工访问 PIN；共享环境应设置独立值 |
| `HOST` / `PORT` | 默认 `127.0.0.1` / `3000` |
| `DATABASE_PATH` | SQLite 文件位置；默认 `data/squarebox.sqlite` |
| `PUBLIC_BASE_URL` | 二维码使用的外部站点地址 |
| `COOKIE_SECURE` | HTTPS 部署时设为 `true`，仅通过 HTTPS 发送会话 Cookie |
| `SQUAREBOX_AI_API_KEY` | 可选的 OpenAI 解读凭证，优先于兼容变量 `OPENAI_API_KEY` |
| `SQUAREBOX_AI_MODEL` | 可选模型名；默认 `gpt-4.1-mini` |

无 AI 凭证时，账目计算、报表、库存和规则建议仍可使用。配置模型只开启汇总数据解读，不允许助理自动采购、修改账目、付款或提交发票；请求会将所选期间的经营汇总发送给 OpenAI，需要相应网络权限。

税率默认 `0`，**不代表已确认 SST 豁免**；实际适用性与税率需按门店注册情况确认。设置中的税率只影响之后建立的新订单。经营利润为净销售额减销售成本及已录入经营费用，不是法定净利润，未覆盖所得税、折旧、退款和未录入费用。

二维码跨设备使用需要手机能访问的地址与相应网络／部署配置；本机回环地址无法供其他设备访问。公开使用前还需完成 HTTPS、独立身份与权限、支付网关、合规及备份方案。当前仅提供基础 PIN 会话与员工接口保护。

数据位于 `data/`，不随 Git 保存。备份运行中的 SQLite 应使用 SQLite 备份 API／一致性备份工具；也可停止服务后备份数据库及存在的 WAL 等关联文件。**不要只复制仍在写入的主数据库文件**，否则可能遗漏 WAL 中的事务。恢复时先停止服务，并在保留原数据后验证备份。

实现与账务口径见 [架构说明](docs/ARCHITECTURE.md)，e-Invoice 的限制及后续接入条件见 [MyInvois 说明](docs/MYINVOIS.md)。
